# Task Management

A small task management app: plain HTML + Tailwind CSS on the frontend,
[Supabase](https://supabase.com) for auth and the database, deployed on
[Vercel](https://vercel.com) as a static site with a build step.

- **Frontend**: static HTML/CSS/JS, no framework or bundler. Tailwind CSS
  is compiled by the Tailwind CLI at build time.
- **Auth + DB**: Supabase (email/password auth, Postgres `tasks` table with
  Row Level Security so each user only ever sees their own tasks).
- **Hosting**: Vercel builds the site (`npm run build`) and serves the
  `public/` directory.

## Project layout

```
public/            # everything Vercel serves
  index.html        # sign in / sign up
  app.html           # task dashboard (requires auth)
  css/styles.css     # generated by `npm run build` (gitignored)
  js/
    config.js        # generated by `npm run build` (gitignored)
    supabaseClient.js
    auth.js
    tasks.js
    app.js
src/input.css        # Tailwind source
scripts/
  generate-config.js  # writes public/js/config.js from env vars
  serve.js             # tiny static file server for local dev
supabase/schema.sql    # tasks table + RLS policies
vercel.json
```

## 1. Create the Supabase project

1. Go to [supabase.com](https://supabase.com) and create a new project.
2. Open the **SQL Editor** and run the contents of
   [`supabase/schema.sql`](./supabase/schema.sql). This creates the `tasks`
   table and Row Level Security policies restricting every row to its owner.
3. Under **Authentication -> Providers**, email/password auth is enabled by
   default — that's all this app needs.
   - Optional: under **Authentication -> Settings**, you can turn off "Confirm
     email" during development so `signUp` returns a session immediately.
4. Under **Project Settings -> API**, copy the **Project URL** and the
   **anon public** key — you'll need both in the next steps.

## 2. Run it locally

```bash
npm install
cp .env.example .env      # then fill in SUPABASE_URL and SUPABASE_ANON_KEY
npm run build              # compiles Tailwind CSS and generates js/config.js
npm run serve               # serves ./public at http://localhost:3000
```

Open http://localhost:3000, create an account, and confirm tasks can be
added, completed, filtered, and deleted.

While iterating on styles, run `npm run dev:css` in a second terminal to
rebuild Tailwind on save (note this doesn't regenerate `config.js`; re-run
`npm run build` if you change `.env`).

## 3. Push to GitHub

This project lives in the `Task_Management` GitHub repo. Commit and push to
a branch, then merge to `main`:

```bash
git add -A
git commit -m "Your change"
git push -u origin <branch-name>
```

## 4. Deploy on Vercel

1. Go to [vercel.com/new](https://vercel.com/new) and import the
   `Task_Management` GitHub repository.
2. Vercel will detect `vercel.json`; the build command (`npm run build`) and
   output directory (`public`) are already configured there, so you don't
   need to change the framework preset.
3. Before the first deploy, add the environment variables from your `.env`
   under **Project Settings -> Environment Variables** (set them for
   Production, Preview, and Development):
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
4. Deploy. Every push to `main` redeploys production; every other branch/PR
   gets its own preview URL with the same env vars.
5. Once deployed, open the Vercel URL and repeat the smoke test from step 2
   (sign up, add/complete/delete a task) against the live site.

## Notes

- The Supabase `anon` key is meant to be public — access control is enforced
  entirely by the Row Level Security policies in `supabase/schema.sql`, not
  by hiding the key. Never use the `service_role` key in this project; it
  bypasses RLS and must never reach the browser.
- There's no server/API layer here: the browser talks to Supabase directly
  via `@supabase/supabase-js`. The library is an npm dependency and its UMD
  bundle is copied into `public/js/vendor/supabase.js` by `npm run build`
  (see `build:vendor` in `package.json`) so there's no CDN dependency at
  runtime.
